# Elastic-Lab-21-ATTACK-Based-Threat-Hunting
## Overview
Threat hunting is the proactive process of searching security telemetry for suspicious behavior that may not have triggered an alert.
Traditional alert-based monitoring starts with an alert and investigates it. Threat hunting starts with a hypothesis and searches for evidence that supports or contradicts it.
For example, a SOC analyst might ask:
Could an attacker have executed PowerShell, established persistence through a scheduled task, and then attempted to hide their activity on this Windows endpoint?

The analyst searches available endpoint logs, examines timestamps and user context, correlates related events, and determines what the evidence actually establishes.

MITRE ATT&CK provides a framework for describing adversary behaviors. It helps analysts organize hunts around techniques rather than relying only on malware names or indicators of compromise.

1. PowerShell — T1059.001
Investigate PowerShell execution, command-line arguments, encoded commands, and the surrounding process activity.

2. Scheduled Task/Job — T1053
Look for task creation or modification that could provide persistence or recurring execution.

3. Impair Defenses — T1562
Investigate suspicious security-control or logging changes. Event-log clearing is specifically associated with T1070.001, Clear Windows Event Logs.

This lab demonstrates a hypothesis-driven threat-hunting workflow using Elastic Security, Elastic Agent 9.5.4, Windows 11 telemetry, and ES|QL. The investigation focuses on identifying potentially suspicious PowerShell execution, scheduled-task activity, and Windows event-log clearing while validating which evidence is actually available in the collected telemetry.

The objective is not to label every unusual event as malicious. Instead, the investigation emphasizes evidence validation, event visibility, behavioral context, MITRE ATT&CK mapping, and transparent documentation of investigative limitations.

## Lab Scenario

You are a SOC Analyst conducting a proactive threat hunt on a Windows 11 endpoint monitored by Elastic Agent 9.5.4 and managed through Elastic Cloud Fleet. Although the agent is healthy and fresh endpoint events are arriving in Kibana Discover, the presence of telemetry alone does not guarantee that every security-relevant Windows event is being generated or collected.

Your objective is to investigate whether the available endpoint logs contain evidence of suspicious process execution, scheduled-task activity, or possible Windows event-log clearing. Using ES|QL, you will examine relevant event IDs, inspect event details, and correlate timestamps and host or user context to determine whether the observed activity warrants further investigation.

During the hunt, some queries may return numerous process-creation events, while others may return only one document or no matching results. You must determine what these results actually establish rather than automatically classifying them as malicious or benign.

### Investigation Tasks

- Review available event datasets and event IDs to understand the endpoint's telemetry coverage.
- Hunt for process creation and PowerShell-related activity, examining command lines and process context where available.
- Investigate scheduled-task creation or modification events and verify the complete event details before assessing their significance.
- Search for Windows event-log clearing indicators and determine whether the relevant logs and time ranges provide sufficient visibility.
- Map supported behaviors to MITRE ATT&CK and document any telemetry gaps or unresolved questions.

### Expected Outcome

Produce an evidence-based threat-hunting assessment that records the queries executed, observations made, relevant timestamps, ATT&CK mappings, and recommended follow-up actions. Clearly distinguish confirmed events from investigative hypotheses and acknowledge when the available telemetry is insufficient to reach a conclusion.

The exercise takes place in a controlled personal SOC lab. No actual compromise is assumed, and the absence of matching events must not be interpreted as proof that the investigated activity never occurred.

## MITRE ATT&CK Relevance

| Behavior under investigation | ATT&CK reference |
|---|---|
| PowerShell execution | T1059.001 — PowerShell |
| Scheduled-task-based persistence or execution | T1053 — Scheduled Task/Job |
| Clearing Windows event logs | T1070.001 — Clear Windows Event Logs |

These mappings describe behaviors under investigation, not confirmed attacker activity. A technique should only be reported as observed when the available evidence supports that conclusion.

## Evidence and Limitations

The investigation confirmed that process telemetry was available and that the relevant ES|QL searches executed successfully. However, query results alone do not establish that malicious activity occurred.

The single scheduled-task query result requires inspection of its complete `event.code`, `event.dataset`, and message fields. The absence of event IDs 1102 and 104 in the selected time range does not establish that log clearing never occurred.

The availability of Security Event IDs 4688, 4698, 4702, 1102, and PowerShell logging events depends on Windows audit settings, event-channel collection, and integration configuration.
